# 2026-02-23 Linux 0.01 Boot Process Note

## cs 와 eip

cs:
- code segment register
- using as an offset of the instruction pointer
- changed by calling JMP, CALL, interrupts, exceptions
- 현재 실행하는 명령어 집합이 위치한 세그먼트를 저장
- eip 값을 오프셋으로 활용
- cs 값은 control-transfer 명령(3.5 Control Transfer Instructions)으로만 암시적으로 변경됨. (직접 변경하지 않음)
  - JMP, CALL, RET, IRET, 명령어들.
  - 세그먼트간의 이동(far jump)일수도 있고, 동일 세그먼트 내부(near jump)에서의 이동일 수도 있음

eip:
- instruction pointer
- contains the offset address, relative to the start of the current code segment
- 현재 코드세그먼트 시작점으로부터의 오프셋
- 이것도 직접제어가 아니라 control-transfer 명령에 의해 암시적으로 변경됨

- logical address 에서 linear address로의 변환이 필요함
- logical address는 selector(16-bit)와 offset(32-bit)으로 구성. 이게 무슨주소야...? 어디에 저장되는거?
 : 이게 complete pointer 라고 하는데.
 : real-address mode에서는 이 주소가 곧 물리 주소다. 뒤에 세그먼트 디스크립터 관련 참고

## 플로피 디스크 복사
이제 플로피 디스크에 있는 시스템 이미지 내용물을 0x10000 물리메모리로 복사함


### 1.44MB 플로피 디스크
- 1.44MB = 1,440KB = 1,474,560 bytes
- double side
- tracks per side: 80, totally 160 track
- sectors per track: 18
- bytes per sector: 512
: total sectors: 2,880


```
side 0       track 0           track 1      ...     track 79
          +-----------+     +-----------+         +-----------+
sector 17 | 512 bytes |     | 512 bytes |         | 512 bytes |
          +-----------+     +-----------+         +-----------+
          |    ...    |     |    ...    |         |    ...    |
          +-----------+     +-----------+         +-----------+
sector 2  | 512 bytes |     | 512 bytes |         | 512 bytes |
          +-----------+     +-----------+         +-----------+
sector 1  | 512 bytes |     | 512 bytes |         | 512 bytes |
          +-----------+     +-----------+         +-----------+
sector 0  | 512 bytes |     | 512 bytes |         | 512 bytes |
          +-----------+     +-----------+         +-----------+
```

```
read_it->rp_read->ok1_read->ok2_read->read_track->ok4_read->ok3_read -
             +--------------------------------------------------------
```

```asm
sread:
        .word 1            ; sectors read of current track, 0x0001
head:
        .word 0            ; current head, 0x0000
track:
        .word 0            ; current track, 0x0000

read_it:
        mov ax, es         ; es = 0x1000, ax = 0x1000(4096:4K)
        test ax, #0x0fff   ; 0xfff = 4095

die:
        jne die            ; es must be at 64kB boundary
        xor bx, bx        ; bx is starting address within segment   , change to 0

rp_read:
        mov ax, es            ; ax=0x1000
        cmp ax, #ENDSEG       ; have we loaded all yet?, ENDSEG=0x5de3(24035)
        jb ok1_read
        ret

ok1_read:
        mov ax, #sectors     ; ax=18=0x12
        sub ax, sread        ; ax-=0x0001 (18->17->16->...)
        mov cx, ax           ; cx=0x90018->0x90011
        shl cx, #9           ; cx=cx<<9, point to next sector.
        add cx, bx
        jnc ok2_read
        je ok2_read
        xor ax, ax
        sub ax, bx
        shr ax, #9

ok2_read:
        call read_track      ; read one track? 512*18 bytes?
        mov cx, ax
        add ax, sread
        cmp ax, #sectors
        jne ok3_read
        mov ax, #1
        sub ax, head
        jne ok4_read
        inc track            ; next track

ok4_read:
        mov head, ax
        xor ax, ax

ok3_read:
        mov sread, ax
        shl cx, #9
        add bx, cx
        jnc rp_read
        mov ax, es
        add ax, #0x1000
        mov es, ax
        xor bx, bx
        jmp rp_read

read_track:
        push ax
        push bx
        push cx
        push dx
        mov dx, track
        mov cx, sread
        inc cx
        mov ch, dl
        mov dx, head
        mov dh, dl
        mov dl, #0
        and dx, #0x0100
        mov ah, #2
        int 0x13
        jc bad_rt
        pop dx
        pop cx
        pop bx
        pop ax
        ret
```


## real address mode
- 8086 시스템 등과의 호환을 위함
- 1M + 64K 메모리 공간을 제공함  (이것도 잘못됨. 1M+64K 가 아니라, 1M영역중 상위 64K를 의미함)
  - 1M 메모리공간을 제공하려면,
    - 1024*1024 byte
    - 2^10 * 2^10
    - 20 비트가 필요
  - 64K 메모리 공간을 제공하려면,
    - 64*1024 byte
    - 2^6 * 2^10
    - 16 비트가 필요

- 20-bit base
  - segment selector << 4 가 세그먼트 베이스 어드레스(segment selector)
    - 20비트 중 하위 4비트는 0으로 채우기 때문
- 20-bit offset
  - 상위 4비트를 0으로
  - 그리고 base와 더해서 effective address가 됨
- 21-bit linear address
  - base+offset으로 20비트 이지만, carry가 발생할 수 있음
  - 이 때, 8086에서 캐리는 무시되지만, 80386에서는 최상위비트(20)에 할당

> 이 모드에서는 paging이 제공되지 않으므로 linear adderss=physical address

즉, cs << 4 + ip = linear(phy) address

## gdt 초기화
```
lgdt gdt_48

gdt:
        ; first descriptor
        .word 0,0,0,0        ; dummy

        ; second descriptor
        .word 0x07FF        ; 8Mb - limit=2047 (2048*4096=8Mb)
        .word 0x0000        ; base address=0
        .word 0x9A00        ; code read/exec
        .word 0x00C0        ; granularity=4096, 386

        ; third descriptor
        .word 0x07FF        ; 8Mb - limit=2047 (2048*4096=8Mb)
        .word 0x0000        ; base address=0
        .word 0x9200        ; data read/write
        .word 0x00C0        ; granularity=4096, 386

gdt_48:
        .word 0x800          ; gdt limit=2048, 256 GDT entries
        .word gdt, 0x9        ; gdt base = 0X9xxxx
```

lgdt 명령은 뒤의 정보를 gdtr 레지스터로 가져온다.
- lgdt 가 로드하는 주소는 선형 주소(linear address)의 base와 limit이다.
- 48-bit 크기다.(6 바이트)


GDTR register
- store the base address + the segment limits
- if 16-bit operand
  - 16-bit limit
  - 24-bit base
- if 32-bit operand
  - 16-bit limit
  - 32-bit base
  : totally 48-bit(6-byte)
  : high-order 8-bit = base address bits (0x9)

16-bit limit 가 0x800
32-bit base가 gdt, 0x9 다.
그럼 32비트 베이스 주소는
```
  xx xx 00 09
```

여기서 최상위 8-bit가 0x9 이므로 base 주소를 나타냄.

최종 gdt의 메모리 뷰는,
```


  +-----------------+  0x9XA8
  |  00C0  |  9200  |
  |  0000  |  07FF  |
  +-----------------+  0x9XA0
  |  00C0  |  9A00  |
  |  0000  |  07FF  |
  +-----------------+  0x9XX8
  |    0   |    0   |
  |    0   |    0   |
  +-----------------+  0x9XXXX

```

이 전에 이미 do_move를 통해서 0x9000 세그먼트에 시스템이미지가 복사되어 있는 상태
