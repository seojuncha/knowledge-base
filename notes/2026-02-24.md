## Floppy read in boot.s: memory view and register flow

### 1. Invocation and constraints
Entry: read_it is called with ES = 0x1000 (system load segment from SYSSEG).
Check: test ax, #0x0fff on ES ensures the load starts on a 64 KB boundary (ES must be a multiple of 0x1000); otherwise the code spins in die.
Initial registers: ES = 0x1000, BX = 0. So the first load goes to ES:BX = 0x1000:0 → linear address 0x10000.
Memory view at start:
One “current” 64 KB segment at 0x10000; ENDSEG = SYSSEG + SYSSIZE is the first segment we must not load into.

### 2. Outer loop: rp_read — segment and “are we done?”
AX = ES (current segment).
Compare: cmp ax, #ENDSEG. If ES ≥ ENDSEG, we’re done → ret.
So we keep loading while ES &lt; ENDSEG. Progress is by advancing ES by 0x1000 (next 64 KB) when the current segment is full.
Memory view:
We conceptually fill segments 0x1000, 0x2000, … up to (but not including) ENDSEG. Each segment is one 64 KB block (e.g. 0x10000–0x1FFFF, 0x20000–0x2FFFF, …).

### 3. How many sectors to read: ok1_read
Goal: read as many sectors as we can without crossing the 64 KB boundary at the end of the current segment.
AX = sectors − sread = sectors left on current track (e.g. 18 − sread for a 1.44 MB disk).
CX = AX ≪ 9 = that count in bytes; CX += BX (current offset in segment).
If CX does not carry and is not zero, we can read AX sectors into the current segment → ok2_read.
If we would cross 64 KB (carry or zero after add): AX = (−BX) ≫ 9 = number of sectors that still fit in this segment (bytes left / 512). Then we go to ok2_read with this smaller AX.
So AX at ok2_read is always the number of sectors to read in this call (≤ remaining on track, and never past end of current 64 KB).
Register transition:
AX = sector count for this read; CX is reused later for byte count; BX unchanged here.

### 4. Calling the BIOS: read_track
read_track is called with AX = sector count (BIOS uses AL = number of sectors).
ES:BX is still the current load address (segment from outer loop, offset in segment).
Inside read_track:
DX ← track, CX ← sread+1 (first sector number, 1-based). Then CH ← low byte of track (cylinder), and DX is overwritten with head; DH ← head, DL ← 0 (drive A). The and dx, #0x0100 keeps only bit 8 of the word (head 0 or 1).
int 0x13 with AH = 2: read AL sectors from drive DL, cylinder CH, head DH, starting sector CL, into ES:BX.
On error: bad_rt does reset (int 0x13 with AX=0, DX=0) and retries read_track.
So each call fills ES:BX with AX × 512 bytes from the current track/head/sector position.
Memory view:
Data is written sequentially into the current 64 KB segment starting at offset BX. No crossing of 64 KB within one read_track call because the caller limited AX in ok1_read.

### 5. Updating track/head/sread: ok3_read / ok4_read
AX is still the number of sectors just read. AX += sread → new “sectors read on this track.”
If AX == sectors (track full): switch head or track:
AX = 1 − head → next head (0→1 or 1→0).
If AX ≠ 0: head = AX (we’re on next head), sread = 0.
If AX == 0: we’ve done both heads → track incremented, then head = 1, sread = 0 (implementation: head = AX after inc track and ok4_read sets head, then ok3_read sets sread = 0).
If AX ≠ sectors: sread = AX (partial track), head/track unchanged.
ok3_read: sread is written (either 0 or new partial count). CX = sectors read (AX before these updates); CX ≪ 9 = bytes read; BX += CX.
So: sread, head, track always reflect the next sector to read on the floppy; BX is the next offset in the current segment.

### 6. Advancing within / to the next 64 KB segment
BX += (CX ≪ 9) (CX = sectors just read).
If no carry: we’re still inside the same 64 KB segment → jmp rp_read (same ES, new BX).
If carry: we’ve crossed the segment boundary. Then:
AX = ES + 0x1000 → next segment.
ES = AX, BX = 0, jmp rp_read.
Memory view:
Within a segment we move BX from 0 toward 0x10000 (64 KB). When BX would go past 0xFFFF we switch to ES += 0x1000 and BX = 0, so we never cross 64 KB in one segment. Linear addresses advance: 0x10000…0x1FFFF, then 0x20000…0x2FFFF, etc., until ES reaches ENDSEG.

### 7. Summary table (register / memory roles)
Quantity	Role
ES	Current load segment (64 KB unit). Starts at 0x1000, increases by 0x1000 when BX wraps.
BX	Offset inside current segment (0 to 0xFFFF). Increases by (sectors read × 512); zeroed when ES steps.
AX (in loop)	Sector count for next read; then used to update sread/head/track.
CX (in loop)	Byte count (sectors × 512) used to advance BX.
sread	Sectors already read on current track (1-based “next sector” minus 1).
head	Current head (0 or 1).
track	Current cylinder.
So: the floppy is read track-by-track (and head-by-head), while the memory view is a linear sequence of 64 KB segments starting at 0x10000, filled in order without ever crossing a segment boundary in a single BIOS read. Registers ES and BX together form the current load pointer; AX/ CX drive how much we read and how much we advance BX and ES.
